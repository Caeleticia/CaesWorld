# Cae'sWorld · 每个人都能做卡牌

目前三大部分：

1. **动态 UI**：载入页面 + 主菜单。
2. **战斗引擎**：纯逻辑 + 数据存储，回合制战斗、伤害公式、占位/计数、加成系统、内容包与存档。
3. **测试 / 训练场**：构筑双方卡组、配置测试参数，直接开一局带卡面 / 实时数据 / canvas 特效的战斗。

引擎本身仍然不含界面，也不生成关卡。

---

## 运行

本项目是纯静态页面，但**不能直接双击 `index.html`**：`file://` 下浏览器会按 CORS 拦掉 `data/tips.txt` 的读取（界面仍然能用，会自动回落到内置的同一组字符库）。起一个静态服务器即可：

```bash
cd CaeAdventure
python3 -m http.server 8771 --bind 127.0.0.1
# 打开 http://127.0.0.1:8771/index.html
```

`index.html` 声明了 `<base href="./">`，部署在子目录下也能正确解析 `js/ css/ data/ assets/`。

## 界面

### 载入页面
- 大标题 `Cae'sWorld` + 副标题「每个人都能做卡牌」
- 「你知道吗」：从 `data/tips.txt` 抽一条（**同一会话不连续重复**）
- 进度条：铅笔纸槽 + 荧光笔填充 + 流动斜纹 + 笔尖；进度只反映真实启动阶段，不空转
  - `正在启动界面` → `正在加载你知道吗字符库` → `正在加载图片资源` → `正在装配主菜单`
  - 右侧百分比，状态行带动态省略号；100% 后短暂停留再淡出进入主菜单

### 主菜单
- **左侧边栏**（手机竖屏时为顶部卡片，大标题同样保留）
  - 品牌：大标题（小号）+ 副标题
  - 你知道吗小纸条（可点右上角 `↻` 手动换一条，每 9 秒自动换）
  - 标签 + 弹出选项（手风琴：同时只展开一个，再点一次收起；`Esc` 收起）
    - 游玩：同屏 / 肉鸽 / 无尽 / 挑战
    - 测试：训练场
    - 设计：卡牌库 / 编辑器
    - 模组：模组管理
    - 设置：设置
- **右侧头图**
  - 每次进入主菜单时从 `assets/banner/index.txt` 里随机抽一张（banner 文件夹的图片都登记在里面），显示在右侧
  - 载入页不显示头图

### 响应式
- 宽屏：左侧边栏 300px + 右侧展示区
- 平板：边栏收窄到 250px
- 手机竖屏：上下布局，边栏变成顶部卡片（品牌大标题、你知道吗、标签），展示区在下

## 测试

本项目**不保留测试文件**。改完代码请手动走一遍：载入页进度条 → 主菜单 → 编辑器里建角色 / 拖积木 / 连线 / 看 JSON → 导出卡包再导入；

## 开屏头图（banner）

- 图片放在 `assets/banner/`，由同目录下的 `assets/banner/index.txt` 列出：**每行一个文件名**。
- 新增图片：把文件丢进 `assets/banner/`，再在 `index.txt` 里加一行文件名（`#` 开头是注释，空行忽略）。
- 每次进入主菜单时从 `index.txt` 里随机抽一张，显示在**右侧**（载入页不显示头图）；同一次打开不连抽同一张。
- 读取失败（比如用 `file://` 直接打开）会回落到代码里的同一批文件名，界面不会空着。
- 想固定看某一张：地址加 `?banner=peach.png`。

## 卡面图片

卡面优先从**模组 zip 的 `images/`** 里取（见下一节）；模组没有提供时才回落到散图目录。

- 模组内的命名：单位 id `modname_unit_unit1` → `images/unit1.jpg`（取 id 最后一个字段，扩展名不限）。
- 散图默认目录是 `assets/picture/cards/`，路径框默认填「卡牌的短 id.png」：例如 `default_unit_slime` → `assets/picture/cards/slime.png`，`study_unit_littleempire` → `littleempire.png`。
- 也允许直接写路径：`assets/banner/castorice.png`、`./assets/...`、`/assets/...`、`http(s)://...`、`data:` / `blob:` URL 都按原值使用（反斜杠会转成 `/`，空格 / 中文会做 URL 编码）。
- `image` 为空时：先查所属模组 zip 的卡面，没有再用默认「短 id.png」；点「用占位图」会把 `image` 设为 `null`，强制使用内置占位卡面；「选择图片」会把本地图片读成 data URL 内嵌进工程。
- 解析规则在 `engine/editor.js` 的 `registerModImages()` / `CARD_IMAGE_DIR` / `defaultCardImageName()` / `cardImagePath()` / `resolveCardImage()` / `resolveImage()`，编辑器、卡牌库、训练场、战斗界面共用同一套。

## 修改字符库

直接编辑 `data/tips.txt`，每行一条，# 开头也会当成普通文本（不做注释）。文件读取失败时使用 `js/tips.js` 里的 `FALLBACK_TIPS`，增删条目时记得同步这两处。

## 模组 / 卡牌库

### 模组包（ZIP）

推荐每个模组打成一个 ZIP，卡面就存在包里：

```
modname.zip
└── modname/
    ├── images/
    │   ├── unit1.jpg
    │   └── unit2.jpg
    ├── icons/
    │   ├── skill/
    │   │   └── choco.png
    │   └── effect/
    │       └── math.png
    ├── modname.json
    └── README.md
```

- `modname`：模组名，同时也是卡包 id（卡 id 的第一段）；zip 文件名、外层目录、json 文件名三者一致。
- `modname.json`：卡包内容，支持三种形状：
  - 卡包文件 `{ schema, kind: "caeworld-pack", id, name, units, skills, effects }`（编辑器「导出卡包」生成的 zip 里的 `modname.json`）；
  - 旧工程 JSON（`kind: "caeworld-editor-project"`）；
  - 内容包 `{ modname, version, description, units, skills, effects }`。
- `images/`：单位卡面。单位 id 为 `modname_unit_unit1` 时，文件名取**最后一个字段**：`unit1.jpg` / `unit1.png` / `unit1.webp`…都行；不在 `images/` 里的格式会被忽略并在模组页给出提示。
- `icons/skill/`、`icons/effect/`：技能 / 效果图标。命名规则与卡面相同：`modname_skill_choco` → `icons/skill/choco.png`，`modname_effect_math` → `icons/effect/math.png`。`image` 字段可留空（按短 id 自动找），也可填显式路径 / URL；`null` 表示强制不用图标。
- `README.md`：模组说明（可缺省）。会在模组管理页展开显示；JSON 没写名字时，用 README 的一级标题兜底。
- 目录容错：JSON 直接放在 zip 根目录也能读；但按规范应当带 `modname/` 一层。
- **旧 JSON 模组仍兼容**：`mods/foo.json` 不打包也能照常加载（没有包内卡面）。
- **默认包也是模组**：`mods/default.zip`（`id` = `default`），卡面同样在包内。
- 加载时会把 `images/`、`icons/skill/`、`icons/effect/` 解成 blob URL 登记到引擎，卡牌库 / 编辑器 / 训练场 / 战斗界面直接用；图片不落回 `assets/`。
- 启用 / 停用只影响浏览器本地（`caeworld:mods:disabled:v1`），不改服务器文件；默认包也可以停用。
- 想直接用 AI 生成一个模组：把 [`MOD-PROMPT.md`](MOD-PROMPT.md) 整段发给它，再追加需求（主题 / 数量）；它会吐出 `<modname>/<modname>.json` 的内容，打包成 zip 即可。提示词里已经写全了字段、积木表、端口与踩坑。

### 打包一个模组

在项目根目录执行（`study` 换成你的模组名）：

```bash
# 有 zip 命令（在 mods/ 里打包，包里顶层就是 study/）
cd mods && zip -r study.zip study/ && cd ..

# 没有 zip 命令（Termux 常见）：用 Python
python3 -c "import shutil; shutil.make_archive('mods/study', 'zip', 'mods', 'study')"
```

然后把文件名写进 `mods/index.txt`（每行一个，`#` 开头是注释）：

```
default.zip
study.zip
```

### 导入 / 导出

- 模组管理页「导入模组」支持 `.zip` 与旧的 `.json`：ZIP 存进 IndexedDB（含卡面 / 图标），JSON 存 localStorage。
- 「导出」：**一律导出 `.zip`**。ZIP 模组原样还原（服务器模组重新打包）；旧 JSON 模组会现打包成 zip，卡面一并带上。
- 服务器上的模组仍然只能手动放进 `mods/` 并写 `index.txt`。

### 卡牌库

主菜单 → 设计 → 卡牌库（或地址后加 `#library`）。汇总**默认包（`mods/default.zip`）+ 已启用模组 + 编辑器工程**里的所有单位 / 技能 / 效果：

- 按单位 / 技能 / 效果切换；
- 用「全部卡包 / 默认包 / 模组包」筛选；
- 用关键字搜索名字、id、标签或介绍；
- 单位显示品质、HP/ATK/DEF、技能数；技能显示类型与流程块数；效果显示倾向、层数与触发数。
- **点任意一张卡牌可查看详情**：角色会展示角色介绍、完整数值、抗性与已挂载技能的说明；技能展示类型、触发、流程概要与关联角色；效果展示层数、消耗、属性修正与触发。详情里的技能 / 关联角色还能继续点进去。技能 / 效果有图标时卡片和详情都会显示图标，没有图标时继续用首字字形。

### 模组管理

主菜单 → 模组 → 模组管理（或地址后加 `#mods`）。显示服务器模组与本地导入模组，可启用 / 停用、导出、删除。

- 服务器模组会按 `mods/index.txt` 缓存在浏览器 IndexedDB 里；再次打开先读缓存，并用 HEAD 校验文件大小 / ETag / Last-Modified，发现变化才重新下载。如果服务器改了内容但大小和这些校验头都没变，点「刷新」或删除该包缓存。
- 每行都有删除按钮：本地导入项会从 localStorage / IndexedDB 永久删除；服务器模组只删除浏览器缓存，不会改服务器文件，点右上角「刷新」或重新打开页面会重新从服务器缓存。
- 「刷新」还会把本页删掉的服务器模组放回清单，并强制重新下载全部服务器模组。
- 编辑器工程里的同名卡仍优先于模组内容；要看到模组的新版本，除了清缓存，还要处理编辑器里的旧副本。

### 设置 / 清除浏览器数据

主菜单 → 设置（或地址后加 `#settings`）。

- 「清除所有浏览器数据」会删除当前站点在浏览器里保存的：编辑器工程 / 草稿 / 删除标记、本地导入模组与启用状态、训练场设置 / 阵容 / 卡组、导出临时备份，以及 Cache Storage / IndexedDB。
- 清除后自动重新载入，并重新从服务器读取 `mods/`、`data/`、`assets/`。
- 只清除浏览器端数据，**不会删除服务器上的任何文件**；服务器上的默认模组、图片和代码不受影响。

# 战斗引擎

只做逻辑与数据存储：没有关卡、没有 UI。全部代码在 `engine/`，浏览器和 Node 都能直接 `import`：

```js
import { ContentRegistry, createBattle, serializeBattle, restoreBattle } from "./engine/index.js";
```

## 分层

| 文件 | 内容 |
| --- | --- |
| `constants.js` | 四系属性、品质、技能类型、单位默认数值、id 规则 |
| `math.js` | 四系表工具、浮点近似、可复现随机（mulberry32） |
| `units.js` | 单位卡：默认值、规范化、校验 |
| `skills.js` | 技能卡：默认值、校验、效果列表 |
| `modifiers.js` | 效果加成累加器（所有「加成」的唯一入口） |
| `stats.js` | 实时面板：攻击力 / 防御力 / 生命值 / 暴击 / 三系抗性（本源无抗性） |
| `damage.js` | 伤害公式（纯函数，返回完整过程记录） |
| `targeting.js` | 站位、占位、计数、索敌 |
| `buffs.js` | 运行时效果（持续次数、标签、属性限定） |
| `registry.js` | 内容注册表（单位卡 / 技能卡 / 效果卡） |
| `battle.js` | 回合制战斗流程与事件 |
| `storage.js` | 内容包校验、战斗存档、槽位 |
| `editor.js` | 编辑器工程 / 卡包：卡包文件生成、卡包清单迁移、效果属性修正归一化 |

## 单位卡

```jsonc
{
  "name": "史莱姆",
  "id": "default_unit_slime",        // 扩展包_类型_标识，类型段必须是 unit
  "quality": "white",                // white / blue / gold / rainbow（白/蓝/金/彩）
  "level": 90,
  "baseHp": 5000,
  "baseAtk": 1000,
  "baseDef": 500,
  "critRate": 0.05,
  "critDamage": 0.5,
  "speed": 100,                      // 新增：只决定行动顺序（默认 100）
  "resistances": { "physical": 0.05, "magic": 0.05, "spirit": 0.05 },
  "label": "",                       // 可选标签（≤ 40 字）
  "description": "",                 // 角色介绍：卡牌库详情里展示
  "occupiesSlot": true,              // 是否占位
  "countsAsUnit": true,              // 是否计数
  "invincible": false,               // 是否无敌（无条件）
  "obtainable": true,                // 可获取（默认 true；同屏模式首次出现时不可获取的卡自动进 ban 区）
  "skills": ["default_skill_slimebeat"],
  "bonuses": []                      // 可选：条件加成 / 常驻 buff（格式见「效果加成」）
}
```

百分比一律存小数（5% = `0.05`）。省略的字段取默认值（`createUnitCard` 会补全）。

本源是真实伤害，`resistances` 只有 `physical / magic / spirit` 三系；旧数据里的 `origin` 抗性会被忽略。

单位卡**没有**初始效果字段：效果只能在战斗中用「附加效果」积木附加（旧数据里的 `effects` 会被忽略）。

### 要不要有速度？

需求里没写速度，但不写速度就定不了行动顺序。所以给了默认 `speed: 100`，同速按站位先、再按入场顺序；不需要时所有单位同速即可。**如果你有别的行动规则（例如固定先手、轮流制、出手次数），告诉我改。**

## 技能卡

```jsonc
{
  "name": "黏液拍击",
  "id": "default_skill_slimebeat",   // 类型段必须是 skill
  "type": "active",                  // active 主动 / passive 被动
  "valueSource": "atk",              // 技能指定的数值：实时攻击力（默认）或固定数字
  "targets": 1,
  "requiresTarget": true,
  "effects": [                       // 省略 = 单体伤害
    { "kind": "damage", "target": "enemy" },
    { "kind": "buff", "target": "self", "buff": { "label": "守势", "tags": ["guard"], "duration": 2, "def": { "defPct": 1 } } },
    { "kind": "dispel", "target": "enemy", "tags": ["guard"] }
  ]
}
```

`buff.def` 可以直接写 `"atkFlat": "ATTACKER"`，施放时替换成施放者当前攻击力。

技能本身不带属性与倍率：伤害由流程里的「攻击」积木完成，属性与数值都在积木上指定。数据式旧接口的伤害效果可用 `attribute` 指定属性（省略按 `physical`）。

**被动技能**（`type: "passive"`）不用施放：它流程里的「触发」积木会随对应事件自动运行，和效果卡的触发是同一套广播。没有触发积木的被动技能不会做任何事。「始终」属于数据更新事件——单位入场（战斗开始 / 从牌组出场 / 召唤）、扣血、附加效果等都会广播数据更新，而且**任意单位的数据更新都会让所有「始终」被动重新结算一次**。所以「在场时我方 +40%」这类光环会在自己入场时结算，也会在之后有角色入场时补挂给新角色。

一个技能流程可以放多个「触发」积木，每个触发的后续积木只接在它自己后面。主动技能释放时执行所有 `skillCastSelf`（单位释放该技能）触发，各跑各的分支；技能上的其他事件触发（退场 / 入场 / 受击等）无论主动还是被动，都随事件广播执行。主动技能的 `skillCast` / `skillCastSelf` 不会再额外走广播，避免重复执行。

## 效果加成（实时计算）

卡上只有基础数值；所有加成经 `addBonus(acc, bonus)` 进同一个累加器：

- 攻击力 / 防御力 / 生命值：百分比加成 + 数值加成（攻击力降低就是负的百分比）
- 伤害提升百分比、各属性伤害提升百分比（四系）
- 各属性抗性穿透（四系）、抗性降低效果、受到伤害提升效果、易伤效果
- 暴击率、暴击伤害、速度
- 层叠乘子 `atkMul` / `defMul` / `hpMul`（buff、场景效果用）

来源：单位卡 `bonuses`（常驻）→ 运行期 `extraBonuses`（场景修正）→ 当前 `buffs` → **效果属性修正 `attrBonus`**。**每次都现场重算**，没有过期快照。

「效果属性修正」写在效果卡上，效果附着期间给持有者提供面板加成，按层数叠算：

```jsonc
// 效果卡
{
  "id": "custom_effect_guard",
  "name": "守势",
  "attrBonus": [
    { "attr": "defPct",  "value": 0.3 },   // 防御力 +30%
    { "attr": "atkFlat", "value": 100 },   // 攻击力 +100
    { "attr": "physical", "value": 0.1 }   // 物理抗性 +10 个百分点
  ]
}
```

可用 `attr`：`atkPct / atkFlat / defPct / defFlat / hpPct / hpFlat / critRate / critDamage / speed / dmgBoostPct / damageTakenPct / vulnPct / resistDownPct / physical / magic / spirit / attrDmgBoostPct.physical|magic|spirit / attrPenPct.physical|magic|spirit`。百分比一律存小数（5% = `0.05`）。减防也是这个机制：给受击方加负的 `defPct` / `defFlat`；本源是真实伤害，不吃伤害提升也没有抗性，所以没有 `origin` 的伤害提升 / 穿透。一个效果可以有多条，也可以一条都没有。

## 伤害公式

A 打 B，伤害属性 attr：

```
伤害值 = 攻击积木给的数值(默认 A 攻击力)
       × (1 + A 伤害提升%) × (1 + A 对应属性伤害提升%)
       × (暴击 ? 1 + A 暴击伤害 : 1)

防御减伤率 = 1 − (5×A等级 + 500) / (B防御力 + 5×A等级 + 500)
抗性减伤率 = B对应属性抗性×(1−B抗性降低%) − A对应属性穿透      （可为负 → 额外增伤）
易伤率     = B受到伤害提升效果 × B易伤效果

最终伤害 = 伤害值 × (1−防御减伤率) × (1−抗性减伤率) × (1+易伤率)
```

减防不在公式里单列：减防效果直接给受击方加负的 `defPct` / `defFlat` 属性修正，参与计算的已经是修正后的 B防御力。

数值约定：

- **白板互打**：A攻1000打B防500（等级都 90、抗性 5%）= `1000 × 950/1450 × 0.95 = 622.41`（取整 622）。
- **本源伤害**：无视任何加成、防御、抗性、免伤/易伤/无敌，不暴击；伤害 = 指定数值（本源攻击用**卡面基础攻击力**，不吃加成）。「本源技能里施加的 buff」本身照常生效，只是该次本源伤害不算加成。
- **无视减免（攻击积木勾选）**：只跳过目标侧的防御 / 抗性 / 易伤，攻击方的伤害提升与暴击照常。
- **附加伤害（攻击积木勾选）**：不视为攻击，不吃任何加成与减免、不暴击，伤害 = 指定数值；仍会正常扣血、触发受击与退场，但不会登记「单位攻击时」。
- **无敌**：伤害记 0，计算过程照常返回（`targetInvincible: true`）。
- **防护**：防御减伤率按公式取值（上限 100%）；`(1+x)` 遇到负加成最多归零，不会出现负伤害或「减伤变增伤」。
- **暴击判定**：不传 `crit` 时按 A 的暴击率掷骰（随机源是种子决定的可复现 RNG）。
- `calculateDamage()` 返回完整过程：伤害值、是否暴击、各项系数、最终伤害，跳字直接用它。

## 占位 / 计数 / 索敌

- 每侧有格子（`slotsPerSide`，默认 5），`slot` 是整数，`|slot|` 越小越靠前。
- 占位单位不能和其他占位单位同格；不占位的单位可以叠在任意格子。
- 计数单位才进入索敌的「存活单位」列表；**不计数单位全灭不算输**，默认索敌也会跳过它们。
- 默认索敌：离得最近的计数单位。
- 技能里的非敌方目标（`"self"`，或治疗/增益类）与敌人是谁无关，自动指向行动者本人。

## 战斗流程

```
createBattle({ registry, units: [{ cardId, side, slot }], seed })
  → battle:start → turn:start
  battle.useSkill(index[, { targetRef }])   // 当前行动者使用第 index 个技能
  battle.endTurn()                          // 行动方 buff 计时 -1，轮到下一个单位
  … 某方计数单位全灭 → battle:end（winner）
```

每个事件都带 `seq` / `type` / `turn`，伤害事件带完整计算过程（可直接拿来跳字）。同一次「攻击」积木产生的多目标伤害事件共享 `attackGroup`，表现层可据此把命中动画同时播放；循环体里每轮攻击是不同的 `attackGroup`。`maxCycles`（默认 8）防止无限对局。

单位退场时先执行 `unitExit` 触发（包括嵌套退场），全部处理完才做战斗结算；所以最后一个单位退场时召唤 / 复活出来的单位会先入场，不会被提前判负。

## 数据存储

- 卡包文件：工程 + 内容合并成一份 JSON（`kind: "caeworld-pack"`），由编辑器「导出卡包」生成（外面包一层模组 zip）、导入时整包合并进来；一份文件里同时有 `id / name / version / author / description` 和 `units / skills / effects`，`skills` / `effects` 额外保留编辑器用的 `ui` 与积木 `pos`，战斗引擎会忽略这些字段。
- 卡包 = 一个 ZIP：`modname/modname.json` 存 `kind: "caeworld-pack"` 的内容与编辑器 UI 状态，`modname/images/` 存单位卡面，`modname/icons/skill/`、`modname/icons/effect/` 存技能 / 效果图标，`modname/README.md` 存说明；把 zip 放进 `mods/`，再写入 `mods/index.txt`。默认包 `mods/default.zip` 也走同一条流程。技能 / 效果卡可选 `image` 字段：空 = 按短 id 自动找包内图标，字符串 = 显式路径 / URL，`null` = 强制不用图标。
- 增加 / 修改卡包：编辑器「导出卡包」现在直接产出 `<包 ID>.zip`（`<包 ID>/<包 ID>.json` + `images/` + `icons/skill/` + `icons/effect/` + `README.md`），放进 `mods/` 再写 `index.txt` 即可；也可以直接在模组管理页导入 zip 调试。
- 战斗存档：`serializeBattle(battle, actions)` 只存「单位 id + 站位 + 当前生命 + 状态 + buff + 累计统计 + 操作序列 + 种子」，体积小；`restoreBattle(save, registry)` 用同种子重放操作，并对账（`verified` / `mismatches`），保证读档与当时完全一致。
- 槽位：`createSaveStore(driver)`，默认内存驱动，浏览器里换 `createLocalDriver()`（localStorage）。
- 外部脚本（场景效果、剧情脚本）调 `applyBuff / dealDamage / heal / dispel` 默认不写事件日志，不干扰重放；需要记录时传 `{ log: true }`。

## 设计角色
- 一个工程可以包含多个角色：顶部角色下拉 + 「新建角色」；切换下拉即可换编辑对象
- **删除角色**：下拉右侧「删除角色」。会从工程移除当前角色，并清空流程里引用该角色的积木常量；删除的 id 会记在 `removedUnitIds` 里，重开编辑器不会从内容包补回（只改本地工程，不改模组文件）
- **编辑中卡包**：编辑器标题下方有一个「编辑中卡包」下拉，角色 / 技能 / 效果三个标签共用它；切换标签不会重置，三个下拉列表都只列出这个包里的卡
- 角色表单里有「所属卡包」，可以随时把已有角色切到别的卡包（卡 id 的包前缀、流程里的单位引用会一起改）
- 填写名字、id、品质、等级、基础生命/攻击/防御、暴击率/暴击伤害、速度、标签、三系抗性（本源无抗性）、占位/计数/无敌/可获取（「可获取」默认勾选，目前只是标记，没有玩法读取它）
- 卡面图片路径默认填「卡牌的短 id.png」（如 `default_unit_slime` → `slime.png`）：先取所属模组 zip 里的 `images/slime.*`，没有才从 `assets/picture/cards/` 读，改卡牌 id 的标识段会自动跟着变；也可以填 `assets/...` 相对路径、`/` 开头的绝对路径、`http(s)` / `data:` / `blob:` URL。点「用占位图」强制使用内置占位图；「选择图片」会把本地图片内嵌成 data URL
- 技能 / 效果表单也有「技能图标 / 效果图标」：留空时按短 id 找所属模组的 `icons/skill/` / `icons/effect/`，也可以填完整路径 / URL、选择本地图片或点「用占位图」；「用占位图」会把 `image` 设为 `null`，强制不用图标
- 右侧实时预览卡面，并勾选要「挂载」的技能（技能由角色为主体执行）；挂载列表会显示每张卡的卡包
- 效果不能初始挂载在角色上：只在战斗中用「附加效果」积木附加（见下方「属性修正」）

## 设计技能 / 效果
- 技能：选择/新建技能，填名字、id（`扩展包_类型_标识`）、主动/被动；攻击方式与数值在流程里搭（「攻击」积木上选属性、接数值）
- **技能多个触发**：技能表单「+ 新触发」或积木盒的「触发」都可以放多个触发；每个触发选自己的条件，后续积木接在对应触发后面。新触发默认「单位释放该技能」（`skillCastSelf`）
- 触发积木的「单位集（可选）」是**目标集**输入；接上后，集合里只要有单位满足「条件（可选）」，这条触发流程才继续
- 触发事件新增「我方单位攻击时」（`allyAttack`）：任意我方单位攻击命中后，攻击者同阵营所有单位身上的该事件触发都会执行；流程里的「自己」仍看触发积木的「自己指谁」（`self` 持有者 / `target` 本次攻击者）
- 效果：选择/新建效果，**必选倾向**「正面 / 负面 / 特殊」，可勾「不可解除」，加「触发流程」（每块触发积木对应一条流程，事件在积木上选）；新触发默认「单位行动结束时」（`unitTurnEnd`）
- **删除技能 / 效果**：列表右侧「删除技能 / 删除效果」。技能还会从所有角色的「挂载技能」里移除；两者都会清空流程里对该 id 的常量引用，并记在 `removedSkillIds` / `removedEffectIds` 里，重开编辑器不会从内容包补回
- 效果的「属性修正」：点「+ 添加属性修正」加一行，选属性（攻击力 % / 攻击力值 / 防御力 % / 防御力值 / 生命值 % / 生命值值 / 暴击率 / 暴击伤害 / 速度 / 伤害提升 % / 三系伤害提升 % / 三系穿透 % / 受到伤害提升 % / 易伤 % / 抗性降低 % / 三系抗性）再填数值；可以加多条，也可以一条都不加。效果附着期间这些加成按层数叠在持有者面板上
- 标题下方的「编辑中卡包」是角色 / 技能 / 效果共用的筛选：三个列表都只显示该包里的卡；切换标签、切换编辑对象都不会重置这个选择
- 编辑中卡包选「全部卡包」时，新建的角色 / 技能 / 效果会进入独立的草稿包 `draft`（名字「草稿包」），不会混进默认包
- 当前编辑的角色 / 技能 / 效果都按对象引用，不按 id 查找：改 id 时正在编辑的卡不会丢
- 效果的「层数计数」默认关闭（关闭时永远只有 1 层）；勾选后可填「层数上限」，默认 1，0 表示无上限
- 效果的「颜色」：留空时按倾向自动取色（正面绿 / 负面红 / 特殊黄），也可以点色块调 HEX 或直接输入 `rgb(...)` / `#RRGGBB`；颜色同时用于左上角效果图标或血条上方的进度条
- 效果的「条式显示」默认关闭；勾选后不再显示左上角图标，改为血条上方的进度条（当前/上限），且必须开启层数计数并设置大于 0 的上限
- 条式显示勾选后可再勾「反转条」：进度显示为 `(上限-当前)/上限`；不勾时显示 `当前/上限`
- 效果的「自动消耗」：勾选后，每次该效果的触发流程执行完就消耗 1 层（触发条件未通过时不消耗）；只剩 1 层或未开启「层数计数」时直接移除整个效果。该消耗无视「不可解除」
- 编辑器会载入默认包 + 已启用模组里的角色 / 技能 / 效果（按 id 合并，已有编辑优先）

## 卡包

「工程」和「内容包」合并成 **卡包**：一个卡包就是一份文件，里面同时有卡包信息（id / 名字 / 版本 / 作者 / 说明）和角色 / 技能 / 效果。

- **卡包标签页**：列出工程里的全部卡包，可以新建、改名、改包 ID、查看本包内容、导出本包。
- **新建**：卡包标签页「新建卡包」；新建角色 / 技能 / 效果会进入标题下方选中的「编辑中卡包」，选「全部卡包」时自动进草稿包 `draft`。
- **重命名**：卡包标签页里改「卡包名」，本包所有卡的显示名会同步。
- **修改包 ID**：填新的包 ID 后点「应用包 ID」。会同时修改：卡包清单、本包每张卡 `id` 的包前缀、角色挂载的技能 id、三份删除标记（`removedUnitIds` / `removedSkillIds` / `removedEffectIds`）、以及所有流程里引用这些 id 的积木常量（`unitId` / `skillId` / `effectId`）。包 ID 只能包含字母 / 数字 / `.` / `-`，不能是 `all`，也不能和已有包重复。
- **切换已有卡所属卡包**：角色表单的「所属卡包」，技能 / 效果表单的「所属卡包」；切包会同步改卡 id 与引用。
- **导出**：顶栏「导出卡包」会先让你选择一个卡包；卡包标签页也有「导出此卡包」。导出为 `<包 ID>.zip`：`<包 ID>/<包 ID>.json`（`kind: "caeworld-pack"`，只含本包卡）+ `images/`（单位卡面）+ `icons/skill/`、`icons/effect/`（技能 / 效果图标），都按 id 最后一个字段命名，data URL / blob / 相对路径都会被收进包）+ 自动生成的 `README.md`；如果引用了不在本包内的角色 / 技能 / 效果，状态栏会提示缺了哪些。下载失败（浏览器拦截 / 不支持）时会把 JSON 复制到剪贴板。
- **导入**：顶栏「导入」支持**模组 zip**、卡包文件、旧工程 JSON、旧内容包和单张卡；zip 里的卡面与技能 / 效果图标会内嵌成 data URL 写进工程，再次导出时自动带回；卡包按包 id 合并，同 id 的卡覆盖、其余保留。

## 拖积木（积木块总览）
| 类 | 颜色 | 积木 |
| --- | --- | --- |
| 触发 | 红 | 触发（12 种触发条件 + 始终） |
| 执行 | 橙 | 攻击 / 回复 / 设置血量 / 附加效果 / 移除效果 / 召唤单位 / 召唤子单位 / 跳过行动 / 免疫伤害 / 强制退场 / 给予技能 |
| 结构 | 黄 | 条件分支 / 条件循环 / 遍历循环 / 次数循环 |
| 条件 | 绿 | 比较 / 与 / 或 / 非 / 异或 / 同或 |
| 数据 | 浅蓝 | 数值 / 字符串 / 运算 / 获取单位 / 获取目标集 / 选择单位 / 集合运算 / 获取单位数据 / 自己的数值 / 筛选目标集 / 遍历中的单位 / 单位，外加 3 个补全：遍历中的阵营 / 当前目标 / 触发的单位 |
| 变量 | 紫 | 声明变量 / 读取变量 / 设置变量值 / 增加变量值 |

「攻击」积木有「无视减免」与「附加伤害」两个勾选项（默认都否）：无视减免只跳过目标侧的防御 / 抗性 / 易伤；附加伤害不视为攻击，无视任何加成和减免，也不暴击。**一次「攻击」积木接多个目标 = 一次攻击动作，所有命中同时结算 / 同时播放**；要逐个攻击请把「攻击」放进遍历 / 次数 / 条件循环，循环的每一轮才是独立的依次攻击。

「召唤单位」/「召唤子单位」的单位 id 留空时默认召唤流程拥有者自己；「召唤子单位」的目标集留空时也会回落到自己，方便直接做「分裂」。

「运算」积木的输入口是动态的：普通运算为 `a` / `b`，`max` / `min` 会随已连接数自动长出新输入口。

**变量**只在一次流程执行内有效：每次释放技能 / 触发流程都会重新声明，流程跑完即清空，不跨回合保存；不同技能、不同触发流程之间同名变量互不影响。必须先「声明变量」再读取 / 设置 / 增加：未声明时读取得到空值，设置 / 增加不做任何事。「声明变量」的「值」输入端口类型随变量类型变化（数字 / 字符串 / 布尔→条件），「读取变量」的输出是「任意」，可以接到攻击数值、比较、条件等输入。声明 / 设置 / 增加是执行流积木（有 `in` / `next`），读取是数据积木。

积木是白色圆角矩形，上方一条大类颜色；**上方**是执行流端口（左接上一步、右接下一步），**两侧**是数据端口（左输入、右输出，按数据类型着色）。一个输出可接多个输入，一个输入只接一个来源；执行流输出只能接一个下一步。**「目标」输出可以直接接「目标集」输入**（视为只含该目标的目标集）；反过来「目标集」输出不能直接接「目标」输入。

## 画布操作
- 从左侧积木盒**拖**到画布，或**点一下**积木名直接放到画布中央；选中积木后点「删除积木」
- **长按某个端口再拖**到另一个端口 = 连线（只允许同类型：目标集 / 目标 / 数字 / 字符串 / 条件 / 任意；「目标」也能接「目标集」）
- **工具条滑钮切换「拖拽 / 切割」**：拖拽模式按住画布拖动 = 平移画布；切割模式按住拖动 = 拖过哪条连线就切哪条，期间不会平移画布
- **模板**：技能流程工具条的「模板」按钮会直接追加默认史莱姆「撞击」的技能流程（5 块积木 + 4 条连线）；重复点击会自动生成新 id 并排在已有积木下方
- 工具条：缩放 / 「适应」全览 / **定位**（把视角移到离视口中心最近的积木）/ **整理**（执行流排成一列、数据积木排到左侧，按实测高度下推避免重叠，然后自动适应）/ **模板** / 拖拽·切割滑钮
- 连线/类型不合法时状态栏会提示原因；流程有问题时画布下方红色条列出问题

## 实时 JSON 与存档
- 画布下方**执行流程 JSON**：实时反映积木（id/类型/选项）、连接（from/port/to/portTo）、位置（pos）
- 页面底部**存档 JSON**：当前标签页所在卡包的卡包文件（工程 + 内容合一），「复制卡包」复制的就是它
- 所有改动**自动保存在 localStorage**（按卡组存：`caeworld:editor-project:<卡组>`，默认卡组是 `default`），顶栏可手动「保存 / 导出 / 导入」
- 导出的 `<包 ID>.zip` 可以直接放进 `mods/` 当模组包；编辑器启动时会从默认包 + 已启用模组补入尚未载入的卡
- **导出下载**：只下载一个文件、锚点先挂进文档再点击；浏览器拦截或环境不支持下载时，会自动把 JSON 复制到剪贴板并在状态栏提示

## 与引擎的对应
- 技能：`format: "flow"`，流程由施放者为主体执行；同一流程可以放多个触发积木。主动技能释放时执行所有 `skillCastSelf` 触发（各跑各的分支），技能上的其他事件触发和被动技能一样走事件广播（主动技能的 cast 触发不重复广播）；「技能指定的数值」用「攻击」积木的数值输入
- 效果：`triggers`（积木 id + 事件 + 单位取谁）+ `flows`（按积木 id 对应的流程）；效果卡还带 `polarity`（positive / negative / special）、`stackable`、`maxStacks`、`attrBonus`（属性修正，格式见「效果加成」）、`autoConsume`（自动消耗），以及可选的 `color`、`bar`、`barInvert`（颜色 / 条式显示 / 反转条）。引擎在事件发生时找到这些触发并执行；`autoConsume` 在每次该效果的触发流程跑完后消耗 1 层（只剩 1 层或未开启层数计数时直接移除，且无视「不可解除」）；效果只能战斗中附加，单位卡没有初始效果字段
- 「附加效果」默认只附加 1 层；可以把「层数」接上数值积木，或直接在积木上键入层数（留空 = 1 层）。效果卡勾选「层数计数」后才按层数叠加，上限看 `maxStacks`（0 = 无上限）
- 「移除效果」默认移除 1 层，勾选「强制移除」才能移除不可解除的效果
- 本源（`origin`）伤害不吃任何加成、无视防御/抗性/易伤/无敌，也不暴击；「附加伤害」同样不吃加成与减免，但不会登记为一次攻击

## 说明（我自己补的几处）
- 原「遍历中的单位」只能指代遍历单位，为了让 5-8/5-9 的用法成立，补了「遍历中的阵营 / 当前目标 / 触发的单位」三块数据积木
- 条件分支的两个分支可以汇到同一个下一步；「比较」的输出只接条件类/结构类的条件输入
- 效果触发时「自己」默认是持有者，触发积木上可选「触发事件的单位」

# 游玩 / 同屏

主菜单 → 游玩 → 同屏（或地址后加 `#play`）。同屏采用**抽牌制**，配置界面**不构筑卡组**：牌库本身就是双方的抽牌池，被 ban 的卡不会进入任何一方的牌池。

## 配置
- 横屏 / 桌面（从左到右）：**牌库**、**ban 卡区**、**设置**。
- 竖屏 / 手机：顶端滑钮切换 **ban卡 / 设置**（初始 ban 卡）。
  - ban 卡：牌库 + ban 卡区；
  - 设置：设置 + 开始战斗。
- 牌库可筛卡包 / 搜索；点卡牌加入 ban 卡区，再点一次移出。
- 牌库里的卡不在这里组成红 / 蓝卡组；开战时双方各自复制一份「牌库 − ban」作为抽牌池，互不影响。
- ban 卡区：上方当前 ban 卡，下方已保存 ban 卡组（保存当前 / 点选切换 / `×` 删除）。
- 不可获取（`obtainable: false`）的单位第一次出现时自动放入 ban 卡区，之后玩家可以手动移出，不会再次自动加回。
- 技能缺失、无法安全上场的单位不进入抽牌池，配置页会标「技能缺失 · 不抽」。
- 设置按种类换行分组：场上最多单位；初始抽牌数 / 是否补牌 / 补牌间隔 / 补牌数；允许同名角色；人机红方 / 蓝方；开始战斗。
- 本地存储：`caeworld:local:v2` —— 全部设置、ban 卡区、已保存 ban 卡组、竖屏当前页实时保存；会兼容读取旧的 `caeworld:local:v1`，与训练场 `caeworld:training:v1` 完全分开。

## 战斗界面
- 横屏：左红 / 右蓝 / 下行动栏；左下角红方手牌按钮、右下角蓝方手牌按钮。
- 竖屏：蓝方在上、红方在下，手牌按钮跟随各自卡区。
- 抽牌：每次从剩余牌池随机抽一张，红 / 蓝各自独立随机，不会按固定牌序抽到同一串牌。
- 不允许同名角色时，某方场上或手牌里已有的角色不会再次被该方抽到；剩余牌全是同名角色时，本次不抽牌。
- 初始抽牌进手牌，双方依次布阵：至少上场 1 个，最多「场上最多单位」个；后手布阵完成后正式开战。
- 场上单位数小于上限时，卡区里会出现和卡牌同尺寸的虚线「补上场」格；点它或点手牌按钮，从手牌上场新单位（不消耗行动）。
- 每经过「补牌间隔回合」，双方交替补牌：画布中心先播该方颜色的光环，展示牌背，翻面成卡牌，再缩小飞入对应手牌按钮。
- 一方场上单位全部被击败时：若手牌还有单位，立刻弹出布阵手牌要求补上场；若手牌为空，该方失败。
- 被「跳过行动」的单位会立刻记为已行动，本回合不会再次被选中。
- 人机会从手牌里选出评分最高的牌，把场上补到上限；并在每个行动回合开始前补满。
- 人机会优先选择带特殊效果的技能（尤其是行动开始时生效的负面效果），并优先把控制 / 持续伤害效果施加给尚未行动、威胁最高的敌人。
- 人机会逐个技能估算「当前生命下不溢出的总伤」，优先释放总伤最高的技能；若没有伤害，则选择能施加效果 / 召唤 / 回复的技能，并为单体技能挑选收益最高的敌人。
- 行动、技能、目标选择与训练场共用同一套战斗引擎与卡牌表现。
- 同名限制关闭时，场上 / 手牌里重复名字的单位会变透明且不能从手牌上场。

## 战斗流程（引擎 local 模式）
`createBattle({ mode: "local", decks, maxUnits, initialHand, refillEnabled, refillEvery, refillCount, allowSameName })`：

1. 配置页把「牌库 − ban」分别复制给红 / 蓝，作为双方独立的 `decks`；`startLocal()` 各抽初始手牌，进入 `phase: "deploy"`，红方先布阵、蓝方后布阵；
2. `deployFromHand(side, handIndex)` 从手牌上场；`finishDeploy(side)` 结束当前布阵 / 补上场；
3. 双方布阵完成后进入正常回合：`selectUnit` / `useSkill` / `endTurn`；
4. 场上全灭但手牌不为空时，`advanceSide` 停在 `deploy` 阶段并发出 `deploy:required`；手牌也为空则按 `battle:end` 判负；
5. 回合切换时按设置抽牌，事件为 `hand:draw` / `refill` / `refill:done`。

# 测试 / 训练场

主菜单 → 测试 → 训练场（或地址后加 `#training`）。用来快速验证卡组与积木流程，分「配置」与「战斗」两屏。

## 配置
- 牌库：默认包 + 已启用模组 + 编辑器本地工程里的全部单位（同一 id 以编辑器为准）；每侧牌库都有「全部卡包 / 默认包 / 模组包」筛选。
- 横屏 / 桌面：从左到右 **牌库 1 → 红方卡组 → 蓝方卡组 → 牌库 2**；牌库 1 补红方，牌库 2 补蓝方。
- 竖屏 / 手机：顶端滑钮切换红 / 蓝，下面依次是**牌库**与**该方卡组**。
- 卡组：上方是当前阵容（上移 / 下移 / 移除，入场按这个顺序），下方是已保存卡组（点一下切换、`×` 删除、`＋ 保存当前` 从当前阵容新建）。
- 设置：场上最多单位（默认 4）、红方无敌 / 蓝方无敌（默认否）、人机红方（默认否）/ 人机蓝方（默认是）。
- 本地存储：`caeworld:training:v1` —— 设置、双方当前阵容、已保存卡组、竖屏当前方实时保存（每次改动立即写入）。

## 战斗界面
- 横屏：左红 / 右蓝 / 下行动栏；竖屏：上蓝 / 下红 / 底部行动栏。
- 卡牌 3:4 圆角，底部血条 `hp / maxhp`；卡面外侧是状态 / 效果图标，点图标或卡牌看实时数据。勾选「条式显示」的效果不显示外侧图标，改为血条上方的 `当前/上限` 进度条（反转条显示 `(上限-当前)/上限`）：
  - 数值：`基础数值 + 加成数值`（加号与加成值为蓝色），加成 = 当前值 − 基础值；
  - 角色介绍：单位卡填写了 `description` 时显示在数值上方；
  - 效果：`效果名（开启层数计数时才显示层数）` + 描述；正面 / 负面 / 特殊与常驻 / 增益带标签；
  - 点效果条目或技能可以打开对应介绍，再用「返回角色」回到数据面板。
- 卡牌尺寸按场上单位数量自动排布：**1~4 个单位时保持「4 个单位」的尺寸上限**，只有超过 4 个才继续缩小。
- 人机同样会估算每个技能的「不溢出总伤」，优先总伤最高的技能；没有伤害时选择能施加效果 / 召唤 / 回复的技能，并为单体技能选择收益最高的敌人。
- 行动栏：选单位 → 选技能 → 需要目标的技能再点选目标 / 结束行动；只有 `requiresTarget` 为真、或流程里放了「选择单位」积木的技能才要求玩家手动点目标，全体 / 固定目标 / 纯自身技能直接施放。选好单位但还没选技能时，点其他未行动单位可以换行动单位；选了技能后点「取消技能」回到技能列表。人机方自动选单位、技能与目标。
- 特效全部用 canvas 画：飞弹（中心色弹头 + 2~3 个同色系拖尾粒子）、爆炸（15 个粒子）、光环（扩散双环 + 上升光点）、命中后才跳字（颜色按属性渐变）。**附加伤害不飞弹**：目标卡面上直接收拢碎屑 + 一次冲击环，跳字数字下方带「附加」小标签。
- **不滚页面**：舞台固定设计尺寸（横屏 960×470 / 竖屏 430×900），JS 按视口等比缩放并居中；卡牌与特效都在这套舞台坐标里，所以换屏幕、转屏都不会让特效错位。

## 战斗流程（引擎 side 模式）
`createBattle({ mode: "side", decks: { ally, enemy }, maxUnits, invincibleSides, firstSide: "ally" })`：

每回合：
1. 双方从牌组按顺序补单位，补到「场上最多单位」为止（多出来的单位在后续回合入场）；
2. 触发所有「回合开始时」效果；
3. 默认红方先手，双方交替行动：各有未行动单位时，选 1 个行动 1 次；
4. 一方没有可行动单位时跳过该方；双方都没有 → 触发「回合结束时」效果 → 进入下一回合。

召唤 / 从牌组部署出来的单位**一律视为未行动**：当回合就能被选去行动（只有调用方显式传 `markActed: true` 才记成已行动）。

引擎接口：`battle.selectUnit(uid)` → `battle.useSkill(index, { targetRef })` / `battle.endTurn()`；
`publicBattle()` 会带 `phase / sideTurn / acted / decks / maxUnits / invincibleSides`，界面据此画「本回合已行动」等状态。
