# Cae'sWorld · 每个人都能做卡牌

目前两大部分：

1. **动态 UI**：载入页面 + 主菜单（无玩法内容）。
2. **战斗引擎**：纯逻辑 + 数据存储，回合制战斗、伤害公式、占位/计数、加成系统、内容包与存档。**没有界面，也不生成关卡。**

---

## 运行

本项目是纯静态页面，但**不能直接双击 `index.html`**：`file://` 下浏览器会按 CORS 拦掉 `data/tips.txt` 的读取（界面仍然能用，会自动回落到内置的同一组字符库）。起一个静态服务器即可：

```bash
cd CaeAdventure
python3 -m http.server 8771 --bind 127.0.0.1
# 打开 http://127.0.0.1:8771/index.html
```

`index.html` 声明了 `<base href="./">`，部署在子目录下也能正确解析 `js/ css/ data/ assets/`。

## 界面

- 大标题 `Cae'sWorld` + 副标题「每个人都能做卡牌」

# 战斗引擎

只做逻辑与数据存储：没有关卡、没有 UI。全部代码在 `engine/`，浏览器和 Node 都能直接 `import`：

```js
import { ContentRegistry, createBattle, serializeBattle, restoreBattle } from "./engine/index.js";
```

## 单位卡

```jsonc
{
  "name": "史莱姆",
  "id": "default_unit_slime",        // 扩展包_类型_标识，类型段必须是 unit
  "quality": "white",                // white / blue / gold / rainbow（白/蓝/金/彩）
  "level": 90,
  "baseHp": 5000,
  "baseAtk": 1000,
  "baseDef": 500,
  "critRate": 0.05,
  "critDamage": 0.5,
  "speed": 100,                      // 新增：只决定行动顺序（默认 100）
  "resistances": { "physical": 0.05, "magic": 0.05, "spirit": 0.05, "origin": 0.05 },
  "occupiesSlot": true,              // 是否占位
  "countsAsUnit": true,              // 是否计数
  "invincible": false,               // 是否无敌（无条件）
  "skills": ["default_skill_slimebeat", "default_skill_bloodlust"],
  "bonuses": []                      // 可选：条件加成 / 常驻 buff（格式见「效果加成」）
}
```

百分比一律存小数（5% = `0.05`）。省略的字段取默认值（`createUnitCard` 会补全）。

### 要不要有速度？

需求里没写速度，但不写速度就定不了行动顺序。所以给了默认 `speed: 100`，同速按站位先、再按入场顺序；不需要时所有单位同速即可。**如果你有别的行动规则（例如固定先手、轮流制、出手次数），告诉我改。**

## 技能卡

```jsonc
{
  "name": "黏液拍击",
  "id": "default_skill_slimebeat",   // 类型段必须是 skill
  "type": "active",                  // active 主动 / passive 被动
  "attribute": "physical",           // physical 物理 / magic 魔法 / spirit 精神 / origin 本源
  "multiplier": 1,                   // 或 { "physical": 1.2, "magic": 0 }；省略 = 1
  "valueSource": "atk",              // 技能指定的数值：实时攻击力（默认）或固定数字
  "targets": 1,
  "requiresTarget": true,
  "effects": [                       // 省略 = 单体伤害
    { "kind": "damage", "target": "enemy" },
    { "kind": "buff", "target": "self", "buff": { "label": "守势", "tags": ["guard"], "duration": 2, "def": { "defPct": 1 } } },
    { "kind": "dispel", "target": "enemy", "tags": ["guard"] }
  ]
}
```

`buff.def` 可以直接写 `"atkFlat": "ATTACKER"`，施放时替换成施放者当前攻击力。

## 效果加成（实时计算）

卡上只有基础数值；所有加成经 `addBonus(acc, bonus)` 进同一个累加器：

- 攻击力 / 防御力 / 生命值：百分比加成 + 数值加成（攻击力降低就是负的百分比）
- 伤害提升百分比、各属性伤害提升百分比（四系）
- 各属性抗性穿透（四系）、抗性降低效果、受到伤害提升效果、易伤效果
- 暴击率、暴击伤害、防御减免百分比、速度
- 层叠乘子 `atkMul` / `defMul` / `hpMul`（buff、场景效果用）

来源：单位卡 `bonuses`（常驻）→ 运行期 `extraBonuses`（场景修正）→ 当前 `buffs`。**每次都现场重算**，没有过期快照。

## 伤害公式

A 打 B，伤害属性 attr：

```
伤害值 = 技能指定的数值(默认 A 攻击力) × 技能倍率
       × (1 + A 伤害提升%) × (1 + A 对应属性伤害提升%)
       × (暴击 ? 1 + A 暴击伤害 : 1)

防御减伤率 = 1 − (A等级+10) / (A等级+10 + B防御力×(1−A减防%))
抗性减伤率 = B对应属性抗性×(1−B抗性降低%) − A对应属性穿透      （可为负 → 额外增伤）
易伤率     = B受到伤害提升效果 × B易伤效果

最终伤害 = 伤害值 × (1−防御减伤率) × (1−抗性减伤率) × (1+易伤率)
```

数值约定：

- **白板互打**：A攻1000打B防500（等级都 90、抗性 5%）= `1000 × (100/600) × 0.95 = 158.33`。
- **本源伤害**：无视任何加成、防御、抗性、免伤/易伤/无敌，不暴击；伤害 = 技能数值 × 倍率（本源技能用**卡面基础攻击力**，不吃加成）。「本源技能里施加的 buff」本身照常生效，只是该次本源伤害不算加成。
- **无敌**：伤害记 0，计算过程照常返回（`targetInvincible: true`）。
- **防护**：防御减伤率封顶 99%；`(1+x)` 遇到负加成最多归零，不会出现负伤害或「减伤变增伤」。
- **暴击判定**：不传 `crit` 时按 A 的暴击率掷骰（随机源是种子决定的可复现 RNG）。
- `calculateDamage()` 返回完整过程：伤害值、是否暴击、各项系数、最终伤害，跳字直接用它。

## 占位 / 计数 / 索敌

- 每侧有格子（`slotsPerSide`，默认 5），`slot` 是整数，`|slot|` 越小越靠前。
- 占位单位不能和其他占位单位同格；不占位的单位可以叠在任意格子。
- 计数单位才进入索敌的「存活单位」列表；**不计数单位全灭不算输**，默认索敌也会跳过它们。
- 默认索敌：离得最近的计数单位。
- 技能里的非敌方目标（`"self"`，或治疗/增益类）与敌人是谁无关，自动指向行动者本人。

## 战斗流程

```
createBattle({ registry, units: [{ cardId, side, slot }], seed })
  → battle:start → turn:start
  battle.useSkill(index[, { targetRef }])   // 当前行动者使用第 index 个技能
  battle.endTurn()                          // 行动方 buff 计时 -1，轮到下一个单位
  … 某方计数单位全灭 → battle:end（winner）
```

每个事件都带 `seq` / `type` / `turn`，伤害事件带完整计算过程（可直接拿来跳字）。`maxCycles`（默认 8）防止无限对局。

## 数据存储

- 内容包：`data/units.json`、`data/skills.json`，`validateContent()` 一次报全所有问题（重复 id、缺字段、技能引用不存在）。
- 战斗存档：`serializeBattle(battle, actions)` 只存「单位 id + 站位 + 当前生命 + 状态 + buff + 累计统计 + 操作序列 + 种子」，体积小；`restoreBattle(save, registry)` 用同种子重放操作，并对账（`verified` / `mismatches`），保证读档与当时完全一致。
- 槽位：`createSaveStore(driver)`，默认内存驱动，浏览器里换 `createLocalDriver()`（localStorage）。
- 外部脚本（场景效果、剧情脚本）调 `applyBuff / dealDamage / heal / dispel` 默认不写事件日志，不干扰重放；需要记录时传 `{ log: true }`。

# 编辑器

主菜单 → 设计 → 编辑器（或地址后加 `#editor`）。三个标签：**设计角色 / 设计技能 / 设计效果**。

## 设计角色
- 填写名字、id、品质、等级、基础生命/攻击/防御、暴击率/暴击伤害、速度、标签、四系抗性、占位/计数/无敌
- 卡面图片：填路径（默认用内置占位图）、选本地图片（内嵌成 data URL）、一键回到占位图
- 右侧实时预览卡面，并勾选要「挂载」的技能 / 效果（技能由角色为主体执行，效果挂在角色身上，存在时才可能触发）

## 设计技能 / 效果
- 技能：选择/新建技能，填名字、id（`扩展包_类型_标识`）、主动/被动、属性、倍率
- 效果：选择/新建效果，勾选「负面 / 不可解除」，加「触发流程」（每块触发积木对应一条流程，事件在积木上选）

## 拖积木（积木块总览）
| 类 | 颜色 | 积木 |
| --- | --- | --- |
| 触发 | 红 | 触发（12 种触发条件 + 始终） |
| 执行 | 橙 | 攻击 / 回复 / 设置血量 / 附加效果 / 移除效果 / 召唤单位 / 召唤子单位 / 跳过行动 / 免疫伤害 / 强制退场 / 给予技能 |
| 结构 | 黄 | 条件分支 / 条件循环 / 遍历循环 / 次数循环 |
| 条件 | 绿 | 比较 / 与 / 或 / 非 / 异或 / 同或 |
| 数据 | 浅蓝 | 数值 / 运算 / 获取单位 / 获取目标集 / 选择单位 / 集合运算 / 获取单位数据 / 筛选目标集 / 遍历中的单位 / 单位，外加 3 个补全：遍历中的阵营 / 当前目标 / 触发的单位 |

积木是白色圆角矩形，上方一条大类颜色；**上方**是执行流端口（左接上一步、右接下一步），**两侧**是数据端口（左输入、右输出，按数据类型着色）。一个输出可接多个输入，一个输入只接一个来源；执行流输出只能接一个下一步。

## 画布操作
- 从左侧积木盒**拖**到画布，或**点一下**积木名直接放到画布中央；选中积木后点「删除积木」
- **长按某个端口再拖**到另一个端口 = 连线（只允许同类型：目标集 / 目标 / 数字 / 字符串 / 条件；「目标」也能接「目标集」）
- **长按空白处再滑动 = 切断**指针经过的连线；拖动空白 = 平移画布；工具条里有缩放与「适应」
- 连线/类型不合法时状态栏会提示原因；流程有问题时画布下方红色条列出问题

## 实时 JSON 与存档
- 画布下方**执行流程 JSON**：实时反映积木（id/类型/选项）、连接（from/port/to/portTo）、位置（pos）
- 页面底部**存档 JSON**：整份工程 + 由它生成的内容包（`units / skills / effects`）
- 所有改动**自动保存在 localStorage**（`caeworld:editor-project`），顶栏可手动「保存 / 导出 / 导入」
- 生成的内容包与 `data/units.json` 等格式一致，导入注册表即可直接进战斗（`tests/flow.test.js` 里有完整回路测试）

## 与引擎的对应
- 技能：`format: "flow"`，流程由施放者为主体执行；「技能指定的数值」用「攻击」积木的数值输入
- 效果：`triggers`（积木 id + 事件 + 单位取谁）+ `flows`（按积木 id 对应的流程）；引擎在事件发生时找到这些触发并执行
- 「附加效果」按层数叠加；「移除效果」默认移除 1 层，勾选「强制移除」才能移除不可解除的效果
- 本源（`origin`）伤害不吃任何加成、无视防御/抗性/易伤/无敌，也不暴击

## 说明（我自己补的几处）
- 原「遍历中的单位」只能指代遍历单位，为了让 5-8/5-9 的用法成立，补了「遍历中的阵营 / 当前目标 / 触发的单位」三块数据积木
- 条件分支的两个分支可以汇到同一个下一步；「比较」的输出只接条件类/结构类的条件输入
- 效果触发时「自己」默认是持有者，触发积木上可选「触发事件的单位」
